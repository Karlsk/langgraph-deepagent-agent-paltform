## 1. 实现状态与两套 API 总览

**✅ 官方已实现**：deepagents 返回的是 LangGraph `CompiledStateGraph`（出处：`graph.py::create_deep_agent` 返回类型），因此 LangGraph 运行时的全部流式能力（`stream` / `astream` / `stream_events` / `astream_events`）天然可用；deepagents 在此之上额外提供了**子代理的类型化投影**（`stream.subagents`，出处：官方 event-streaming 文档「Stream subagents」节）。

| API | 版本定位 | 特点 | 建议 |
|---|---|---|---|
| `astream(stream_mode=...)` | 传统（LangGraph 原生） | 原始 chunk 字典流，`stream_mode` 多选；子代理输出需自行解析 `chunk['ns']` namespace | 存量代码 / 需要 `values` 全量快照时可用 |
| `stream_events(input, version="v3")` | v0.6+ 推荐 | 类型化投影迭代器（`stream.messages` / `.tool_calls` / `.subagents`），递归覆盖子代理 | **新代码一律用 v3**（官方文档以 v3 为唯一示例口径） |

> 选型结论：**新代码明确推荐 `stream_events(version="v3")`**。传统 `astream` 仍可用，但官方 deepagents 流式文档已不再以其为主线。

## 2. 传统 API：astream 与 stream_mode

`astream` 是 LangGraph 编译图的原生方法，deepagents 未做包装（出处：`create_deep_agent` 返回 `CompiledStateGraph`，流式行为全部由 LangGraph 运行时承载）。常用参数：

```python
async for chunk in agent.astream(
    {"messages": [...]},
    stream_mode=["updates", "messages", "custom", "values"],  # 可多选
    subgraphs=True,                                              # 同时流出子图（子代理）事件
    config={"configurable": {"thread_id": ...}},
):
    ...
```

| stream_mode | chunk 内容 | 典型用途 |
|---|---|---|
| `"updates"` | 每个节点执行后的 state 增量 | 观察工具节点产出、任务进度 |
| `"messages"` | LLM token 增量（AIMessageChunk） | 逐 token 打字机效果 |
| `"custom"` | 节点内主动发出的自定义事件 | 进度条、阶段性状态 |
| `"values"` | 每步后的完整 state 快照 | 调试 / 需要全量状态（注意 checkpoint 体积） |

子代理区分：`subgraphs=True` 时，子代理（经 `task` 工具委派的子图）的事件会带 **namespace**，chunk 形如 `(ns, payload)`（多 mode 时）或在 chunk 中带 `ns` 字段——`chunk['ns']` 的 namespace 前缀用于区分主代理与并行子代理的输出（出处：LangGraph streaming 语义；deepagents 官方文档以 `stream.subgraphs` 与 `stream.subagents` 的对照说明佐证：「`stream.subgraphs` shows graph execution structure」）。

传统 API 的痛点正在于此：namespace 是图执行结构的原始表达，需要调用方自行解析、过滤、聚合——这正是 v3 投影要解决的问题。

## 3. 新 API：stream_events(version="v3") 类型化投影

v3 API 把「原始事件流」收敛为**类型化投影迭代器**，deepagents 在此之上加了子代理投影（出处：官方 event-streaming 文档全文示例均以 `stream_events(input, version="v3")` 为入口）：

```python
stream = agent.stream_events(
    {"messages": [{"role": "user", "content": "..."}]},
    version="v3",
)

# 顶层（coordinator）投影
for message in stream.messages:        # 主代理消息
    print(message.text)
for call in stream.tool_calls:         # 主代理工具调用
    print(call.tool_name, call.input, call.completed, call.error)

# 子代理投影：每个经 task 委派的子代理一个 handle
for subagent in stream.subagents:
    print(subagent.name, subagent.path, subagent.status)
    for message in subagent.messages:  # 该子代理的消息
        print(message.text)
```

关键语义（出处：官方 event-streaming 文档）：

- **`stream.subagents` 是 deepagents 特有的投影**：「Deep Agents add a subagent projection on top of LangGraph streaming」。投影是轻量的——先发现子代理任务，只有当你访问 handle 上的 messages / tool_calls / values 时才真正打开对应事件流。
- **handle 的 `name` 即子代理配置名**：取自主代理调用 `task` 工具时传入的 `subagent_type`，可直接用于 UI 路由与过滤。
- **可递归嵌套**：`subagent.subagents` 暴露更深层的嵌套委派，逐层结构与 `stream.subagents` 相同（出处：文档「Stream nested work」节）。
- **原始事件仍可访问**：需要跨 coordinator 与全部子代理的精确到达顺序时，直接迭代 `stream` 本体读协议事件，用 `event["params"]["namespace"]` 判别来源（空 namespace = coordinator）。
- 同步用 `stream_events`，异步用 `astream_events`（返回需 `await`）。

工具调用投影的增量能力（出处：文档「Stream tool calls」节）：`call.output_deltas` 提供工具输出的增量流，`call.completed` / `call.error` / `call.output` 给出终态——长耗时工具可以做实时进度回显。

## 4. subagent handle 字段表

每个 subagent handle 暴露与父运行同构的投影（出处：官方 event-streaming 文档「Subagent stream fields」节表格，实测拉取）：

| 字段 | 说明 |
|---|---|
| `.name` | 子代理名，取自主代理 `task` 调用时选定的 `subagent_type` |
| `.messages` | 该子代理发出的消息流 |
| `.tool_calls` | 限定在该子代理作用域内的工具调用 |
| `.values` | 该子代理的 state 值流 |
| `.subagents` | 嵌套的下一层子代理（递归结构） |
| `.output` | 子代理最终 state / 委派任务的完成信号；读取它可作为「等待完成」的同步点 |
| `.status` | 生命周期状态：`started` / `completed` / `failed` / `interrupted` 等 |
| `.path` | 该子代理流的 namespace 路径（对应传统 API 的 ns 概念） |

生命周期跟踪的最小用法（出处：文档「Track subagent lifecycle」节）：只迭代 `stream.subagents` 不访问其内部投影，即可低成本统计 started / completed / failed——不订阅消息流就不会产生消息消费开销。

**`stream.subgraphs` vs `stream.subagents`**（出处：文档「Subagents versus subgraphs」节）：前者暴露图执行结构（内部节点），后者暴露产品语义的任务委派。**面向用户的 UI 一律用 `stream.subagents`**。

## 5. interleave 交错消费与并发消费

coordinator 与子代理的输出天然交错，实时 UI 需要并发消费。官方给出两条路线（出处：文档「Consume concurrently」节）：

**同步代码：`stream.interleave(...)` 交错消费**——把多个投影合并成一条按到达顺序产出的流，逐项标注来源名：

```python
stream = agent.stream_events(input, version="v3")

for name, item in stream.interleave("messages", "subagents"):
    if name == "messages":
        print("[coordinator]", item.text)
    else:
        for message in item.messages:
            print(f"[{item.name}]", message.text)
```

**异步代码：`astream_events` + `asyncio.gather` 并发消费多个投影**：

```python
import asyncio

stream = await agent.astream_events(input, version="v3")

async def consume_coordinator():
    async for message in stream.messages:
        print("[coordinator]", await message.text)

async def consume_subagents():
    async for subagent in stream.subagents:
        async for message in subagent.messages:
            print(f"[{subagent.name}]", await message.text)

await asyncio.gather(consume_coordinator(), consume_subagents())
```

选型提示：SSE 网关这类「单出口」场景，`interleave`（同步）或单个 gather 内的多投影汇聚（异步）都可行；需要严格到达顺序时退到原始事件迭代（第 3 节末）。

## 6. FastAPI SSE 对接模式

本项目现状（出处：`app/api/v1/chatbot.py`，实测阅读）：`POST /chat/stream` 以 `StreamingResponse(event_generator(), media_type="text/event-stream")` 输出 SSE，`event_generator` 内 `async for chunk in agent.get_stream_response(...)` 逐条产出 `data: {json}\n\n`，以 `StreamResponse(content=..., done=True)` 收尾，异常也序列化为一条 error 事件。

对接 deepagents 的映射建议（保持同一 SSE 帧结构，只替换上游事件源）：

```python
# 关键片段：v3 投影 -> 现有 SSE 帧格式（完整可运行示例留给 examples/）
stream = await agent.astream_events(
    {"messages": [{"role": "user", "content": user_text}]},
    version="v3",
    config={"configurable": {"thread_id": session.id}},
)

async def event_generator():
    try:
        async for message in stream.messages:          # 也可 interleave 子代理
            yield sse_frame(StreamResponse(content=await message.text, done=False))
        yield sse_frame(StreamResponse(content="", done=True))
    except Exception as e:                              # 沿用现有错误帧模式
        logger.exception("stream_chat_request_failed", session_id=session.id, error=str(e))
        yield sse_frame(StreamResponse(content=str(e), done=True))

return StreamingResponse(event_generator(), media_type="text/event-stream")
```

对接要点：

- **thread 映射**：deepagents agent 需传 `checkpointer` 才有多轮记忆，`config={"configurable": {"thread_id": session.id}}` 与本项目现有 session 体系一一对应（出处：`graph.py` 的 `checkpointer` 参数透传给 `create_agent`）。
- **子代理可见性**：若启用 subagents，SSE 帧里建议增加 `source` 字段（coordinator / subagent 名），前端用 v3 的 `subagent.name` 直接渲染子代理卡片（出处：官方文档 frontend/subagent-streaming 指引）。
- **限流与观测**：沿用现有 `@limiter.limit(...)` 与 `llm_stream_duration_seconds` 计时包裹（出处：`chatbot.py` 现状），v3 投影不改变这些横切点。
- **背压**：v3 投影迭代器是拉取式（pull-based），天然适配 async generator 的逐帧产出，无需额外缓冲队列。

## 7. 小结

| 要点 | 结论 |
|---|---|
| 实现状态 | ✅ 官方已实现（LangGraph 运行时承载 + deepagents 子代理投影） |
| 传统 API | `astream(stream_mode=["updates"/"messages"/"custom"/"values"], subgraphs=True)`；子代理靠 `chunk['ns']` namespace 区分 |
| 新 API（推荐） | `stream_events(input, version="v3")`：`stream.messages` / `.tool_calls` / `.subagents` 类型化投影 |
| 子代理观测 | 每个 handle：`.name` / `.messages` / `.tool_calls` / `.values` / `.subagents` / `.output` / `.status` / `.path`，可递归 |
| 交错消费 | 同步 `stream.interleave("messages", "subagents")`；异步 `astream_events` + `asyncio.gather` |
| SSE 对接 | 与现有 `/chat/stream` 的 `StreamingResponse` 帧结构兼容，替换事件源为 v3 投影即可 |
| 出处 | 官方 `/oss/python/deepagents/event-streaming` 文档、`tests/unit_tests/test_deep_agent_streaming.py` |

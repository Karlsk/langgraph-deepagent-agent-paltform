## 1. 扩展点清单表

deepagents 的二次开发面收敛为五个扩展点，全部为 ✅ 官方已实现（`CompiledSubAgent` 注入任意图亦 ✅）：

| 扩展点 | 机制 | 关键规则（防踩坑） | 详见 |
|---|---|---|---|
| **自定义 middleware** | `create_deep_agent(middleware=[...])`，实现 LangChain `AgentMiddleware` 协议（`before` / `wrap_model_call` / `wrap_tool_call` / `after` 四钩子） | 与既有项按 **`.name` 同名则原位替换**；新条目**插入核心栈之后、尾部栈（profile extra / prompt-caching / memory）之前**。`FilesystemMiddleware` 与 `SubAgentMiddleware` 登记于 `_REQUIRED_MIDDLEWARE` 受保护——任何 `excluded_middleware` 试图移除它们直接抛 `ValueError`（移除即静默破坏文件工具 / `task` 工具） | [01 章第 2、3 节](./01-架构总览与运行时数据流.md#2-create_deep_agent-组装流程)、[08 章第 2 节](./08-API参考.md#2-返回值与异常) |
| **自定义 backend** | 实现 `BackendProtocol`（文件语义：ls / glob / grep / 读写）；需要 `execute` 执行能力时进一步实现 `SandboxBackendProtocol` | 文件工具、skills、memory、摘要 offload 全部只经 backend API 访问存储，换 backend 不动中间件栈；路径统一 POSIX 约定，平台差异由 backend 自行转换 | [01 章第 5 节](./01-架构总览与运行时数据流.md#5-backends-协议族速览)、[05 章第 6 节](./05-Skill系统.md#6-两种供给方式statebackend-播种-vs-filesystembackend-读盘) |
| **自定义 state** | 两条路：① `create_deep_agent(state_schema=...)` 传 `DeepAgentState` 的 `TypedDict` 子类；② 中间件自带 `state_schema`（官方优先推荐） | 自定义 state 必须继承 `DeepAgentState` 以保留 `messages` 的 `DeltaChannel` 增量 reducer（约束仅靠类型标注，运行时不校验——破坏了不报错、只变慢）；私有字段标注 `PrivateStateAttr`，不会向子代理传播；随声明式 `SubAgent` 编译时下发，`CompiledSubAgent` 不继承 | [01 章第 4 节](./01-架构总览与运行时数据流.md#4-运行时数据流)、[04 章第 3、4 节](./04-Sub-Agent架构.md#3-状态隔离语义)、[08 章第 1 节](./08-API参考.md#1-create_deep_agent-全参数表) |
| **profiles 注册** | `register_harness_profile`（按模型调 harness 行为：prompt 叠加 / `extra_middleware` / 能力裁剪）；`register_provider_profile`（按 provider 调模型构造：`init_kwargs` / `pre_init` / `init_kwargs_factory`，叠加式合并非替换） | 两者均为 beta API；`HarnessProfile` 另支持 **entry-point 插件注册**（第三方包可通过打包元数据自动注册，无需调用方代码）；`excluded_middleware` 不得触碰受保护脚手架、不得用下划线私有名、未命中即 `ValueError` | [01 章第 6 节](./01-架构总览与运行时数据流.md#6-profiles-机制)、[02 章第 2、3 节](./02-LLM集成.md#2-字符串路径resolve_model-与-providerprofile-叠加)、[03 章第 1 节](./03-System-Prompt系统.md#1-组装顺序user--base--suffix) |
| **`CompiledSubAgent` 注入任意图** | `subagents=[{"name": ..., "description": ..., "runnable": <任意含 messages 键的预编译图>}]` | runnable **原样使用**：不继承父 `state_schema`、`interrupt_on`、任何 deepagents 中间件——是「把自己的 LangGraph 图挂进 `task` 委派体系」的逃生通道，也是本项目存量图迁移的最小切口 | [04 章第 1、4 节](./04-Sub-Agent架构.md#1-三形态对比) |

## 2. 性能清单

### 2.1 DeltaChannel 增量 checkpoint：O(N²) → O(N)

`DeepAgentState.messages` 使用 `DeltaChannel(_messages_delta_reducer, snapshot_frequency=50)`：每步 checkpoint 只写增量，每 50 条消息落一次快照，把消息通道的 checkpoint 增长从 O(N²) 降到 O(N)（出处：`graph.py::DeepAgentState`、`deepagents/_messages_reducer.py`，见 [01 章第 4 节](./01-架构总览与运行时数据流.md#4-运行时数据流)）。

实践含义：长会话 + 持久化 checkpointer（如 `AsyncPostgresSaver`）场景收益最大——这是 deepagents 相对手写 `StateGraph` + `add_messages` reducer 的直接性能优势。**自定义 state 时不要用自己的 reducer 覆盖 `messages` 字段**，否则该优化静默失效。

### 2.2 中间件栈顺序与 Anthropic prompt-cache 前缀

两条源码注释写明的设计决策（出处：`graph.py` 装配段，见 [01 章第 3 节](./01-架构总览与运行时数据流.md#3-默认中间件栈完整顺序)、[02 章第 6 节](./02-LLM集成.md#6-prompt-caching-中间件行为)）：

- **profile `extra_middleware` 置于 memory 之前**：`MemoryMiddleware` 更新会改变 system prompt，若在其后再叠中间件，追加内容落在缓存断点之后/破坏前缀稳定性，Anthropic prompt cache 命中率下降；
- **prompt-caching 中间件位于尾部链、`MemoryMiddleware` 之前**：保证 `cache_control` 断点打在「稳定前缀的末端」——记忆内容作为稳定前缀的一部分被缓存覆盖，而断点之后的消息历史天然易变。

对二次开发的约束：

- 自定义中间件**经 `create_deep_agent(middleware=...)` 传入时，插入位置天然在尾部链之前**，不会破坏该结构；但若手工构造 `create_agent` 并自排中间件顺序，须自行维持「改 system prompt 的中间件靠前、prompt-caching 断点打在最后一段稳定内容上」；
- 高频变化的上下文（用户名、当前时间、每请求检索结果）不要进 `system_prompt` 静态串——走 `wrap_model_call` 动态追加至尾部，或直接放对话消息里（本项目现状 `load_system_prompt()` 每请求填 `current_date_and_time`，迁移时应评估把易变槽位移出 prompt 前缀）。

### 2.3 上下文治理三件套

| 机制 | 定位 | 出处 |
|---|---|---|
| `SummarizationMiddleware` | 上下文超限时对历史消息做摘要压缩，主代理与每个声明式子代理默认装配（按各自模型创建）；可被 profile 排除 | [01 章第 3 节](./01-架构总览与运行时数据流.md#3-默认中间件栈完整顺序) |
| 上下文 offloading（`context_hub`） | 大工具输出卸载出消息上下文、存入 backend，按需回读——控制单条工具结果的 token 体积 | [01 章第 5 节](./01-架构总览与运行时数据流.md#5-backends-协议族速览) |
| message eviction（消息驱逐） | 被摘要覆盖的旧消息从工作集中移除，与摘要配合构成「压缩 + 驱逐」闭环；子代理机制同理——中间过程留在隔离窗口，只回传一条 `ToolMessage` 报告 | [04 章第 3 节](./04-Sub-Agent架构.md#3-状态隔离语义) |

选型直觉：**短而多的工具输出靠 offload，长对话靠摘要，整段独立子任务靠 subagent 隔离**——三者正交叠加。

### 2.4 subagent 并发与状态隔离开销

出处：[04 章](./04-Sub-Agent架构.md)。要点：

- **同步 `task` 是阻塞调用**：并发来自模型在一条消息里发起多个 `task` tool_calls（工具层并发执行），不是异步返回；需要非阻塞请上 `AsyncSubAgent`；
- **隔离有成本**：每次 `task` 都做一次入向 state 剥离（`messages` / `todos` / `structured_response` / 私有字段）+ 出向过滤合并，子代理拥有独立编译的中间件栈与独立上下文窗口——委派粒度太细（把几十秒的小活也外包）会放大往返开销；
- **共享 backend 是隐性耦合**：子代理与父代理共享同一 backend 文件空间，`files` 写入会回传父状态；并发子代理写同一文件需自行约定路径分区；
- 子代理模型可降级（spec 单独给便宜 `model`），是控制成本的主要杠杆。

## 3. HITL：permissions / interrupt_on / HumanInTheLoopMiddleware

✅ 官方已实现。三个入口、一个落地中间件（出处：[08 章第 1 节](./08-API参考.md#1-create_deep_agent-全参数表)、[01 章第 3、4 节](./01-架构总览与运行时数据流.md#3-默认中间件栈完整顺序)）：

| 入口 | 语义 | 用法要点 |
|---|---|---|
| `interrupt_on={"edit_file": True, ...}` | 工具名 → 中断配置；在指定工具调用前暂停等人审 | 值可为 `bool` 或 `InterruptOnConfig`；**需要 checkpointer**（中断恢复依赖持久化 state） |
| `permissions=[FilesystemPermission(...)]` | 文件系统权限规则，按声明顺序评估、首个匹配生效，无匹配放行 | `mode`：`allow`（默认）/ `deny` / `interrupt`；含 `interrupt` 模式规则时**自动安装** `HumanInTheLoopMiddleware`，与 `interrupt_on` 合并时用户项按工具名优先（`_merge_fs_interrupt_on`） |
| `HumanInTheLoopMiddleware` | 上述两路的统一落地中间件 | 一般无需手工装配——传 `interrupt_on` 或 interrupt 型 permissions 即自动安装 |

恢复流程与本项目现状对接（出处：`app/core/langgraph/graph.py` 已有同构实现）：中断后 `graph.aget_state(config).next` 非空，经 `graph.ainvoke(Command(resume=审批结果), config)` 续跑——deepagents 编译图走完全相同的 LangGraph interrupt 语义，本项目 `get_response` / `get_stream_response` 里既有的 resume 检查与 `GraphInterrupt` 兜底逻辑可以原样复用。

继承规则提醒（出处：[04 章第 4 节](./04-Sub-Agent架构.md#4-继承规则表)）：声明式 `SubAgent` 默认继承 `interrupt_on` 与 `permissions`（`permissions` 自带则**整体替换**）；`CompiledSubAgent` / `AsyncSubAgent` **不继承**，审批行为需各自配置。注意权限在**工具层**执行，代码直接调 backend 不受约束。

## 4. checkpointer / store 选型

| 选项 | 定位 | 适用 |
|---|---|---|
| 不传 `checkpointer` | 无跨 run 记忆 | 一次性批处理、评估脚本 |
| `MemorySaver`（`langgraph.checkpoint.memory`） | 进程内内存 checkpoint | 本地调试 / 单测 / examples；**重启即丢**，多进程部署不共享 |
| `AsyncPostgresSaver`（`langgraph-checkpoint-postgres`） | Postgres 持久化 checkpoint，异步、连接池友好 | 生产形态；本项目已在 `LangGraphAgent.create_graph` 中装配并可复用 |
| `store`（`BaseStore`） | **跨线程**持久化存储 | 仅当 backend 用 `StoreBackend`（文件需跨 thread 可见）时**必需**——`create_deep_agent(store=...)` 透传给 `create_agent`；`StateBackend` / `FilesystemBackend` 不需要 |

两条硬约束：

- **HITL（第 3 节）必须有 checkpointer**——无 checkpoint 的中断无法恢复；
- `thread_id`（`config={"configurable": {"thread_id": ...}}`）是 checkpoint 的分区键，与本项目 session 体系一一映射；`store` 的 namespace 则由 backend/调用方自行规划，跨会话共享文件才引入，否则多一层存储依赖没有收益。

## 5. 本项目二次开发落地建议

### 5.1 与 app/core/langgraph/ 的集成切入点

现状：`LangGraphAgent` 手写两节点 `StateGraph`（`chat` → `tool_call` → `chat`），`AsyncPostgresSaver` checkpoint，resume 逻辑与 SSE 出口见 [07 章第 6 节](./07-流式输出.md#6-fastapi-sse-对接模式)。迁移切入点按侵入度从小到大：

1. **并存试点（推荐起步）**：不动存量图，新建一个 `create_deep_agent(...)` 编译图作为独立 agent（如专项任务型入口），复用同一连接池产出的 `AsyncPostgresSaver` 与 `thread_id` 映射；`chatbot.py` 的 SSE 帧结构不变，只换事件源为 v3 投影（示例见 `examples/07_fastapi_sse_integration.py`）。
2. **存量图挂子代理**：把现有 `CompiledStateGraph` 经 `CompiledSubAgent(runnable=...)` 注入 deepagents 主代理——零改造复用存量能力，先拿到委派/上下文隔离收益。
3. **整体替换**：`create_deep_agent` 替换 `_chat` / `_tool_call` 手写循环。注意取舍：替换后循环内行为（metrics 计时点、`process_llm_response` 规整、resume 细节）改由中间件钩子承载，需逐项迁移横切逻辑。

### 5.2 与 app/services/llm/ 的集成（重试/回退三路径）

出处：[02 章第 4 节](./02-LLM集成.md#4-重试与回退deepagents-不内置显式声明)（deepagents 无内置重试/回退，🔧）。

| 路径 | 做法 | 取舍 |
|---|---|---|
| ① LangChain 组合子 | `init_chat_model(...).with_retry(...).with_fallbacks([...])` 后直传 `create_deep_agent(model=实例)` | 最省事（示例 `examples/06_retry_fallback_model.py`）；但传入的是外层 `RunnableWithFallbacks` 包内层 `RunnableRetry`，`isinstance(wrapped, BaseChatModel)` 为 False，harness profile 匹配与 `isinstance` 透传分支需实测 |
| ② 自定义中间件包 tenacity | `wrap_model_call` 钩子里用 tenacity 包住 `handler(request)` | 符合项目「重试一律 tenacity」规范，可携带 structlog 上下文与既有异常类型集（`RateLimitError` / `APITimeoutError` / `APIError`） |
| ③ 保留 `LLMService` 供给层 | 由 `LLMService` 产出模型实例后直传 `create_deep_agent(model=实例)` | 保留循环回退 + `bind_tools` 保持 + 总超时预算；注意 deepagents 会自行绑定内置工具，勿预绑定冲突 |

### 5.3 Langfuse tracing 透传

deepagents 返回的是标准 `CompiledStateGraph`，本项目既有的 callback 透传方式**不需要任何改动**（出处：`app/core/langgraph/graph.py` 的 `config["callbacks"] = [langfuse_callback_handler]` 模式）：

- 调用时经 `config={"callbacks": [langfuse_callback_handler], "metadata": {...}}` 传入即可覆盖全部 LLM 调用；
- 子代理经 `task` 委派时，父代理的 callbacks/tags/configurable 由 LangGraph `ensure_config` 自动传播（出处：[04 章第 2 节](./04-Sub-Agent架构.md#2-task-工具调度机制)），子代理 LLM 调用同样进 trace；
- MCP 工具经 LangChain 工具抽象执行，天然在 trace 覆盖内（出处：[06 章第 7 节](./06-MCP集成.md#7-与本项目-fastapi-宿主结合的建议)）。

### 5.4 AsyncPostgresSaver 复用

`LangGraphAgent._get_connection_pool()` 的 `AsyncConnectionPool`（`autocommit=True`、`prepare_threshold=None`、按环境配 `max_size`）可直接喂给 `AsyncPostgresSaver(pool)` 供 deepagents 图使用——**两个图可共享同一连接池与 checkpoint 表结构**（清理逻辑 `clear_chat_history` 已按 `settings.CHECKPOINT_TABLES` 批量删）。注意 `await checkpointer.setup()` 幂等调用即可，无需新建迁移。

### 5.5 依赖版本抬升路径（决策前置）

出处：[README 第 5 节依赖冲突速查](./README.md#5-本地依赖冲突速查)。deepagents 0.7.5 要求 `langchain>=1.3.14,<2.0.0`、`langchain-anthropic>=1.5.4,<2.0.0`，与本项目当前 `langchain>=1.0.5`、`langchain-anthropic>=1.0,<1.1` 冲突。评估建议：

1. **先隔离验证，后动主依赖**：在独立 venv 用目标版本跑现有测试面（`uv run pytest`）+ deepagents examples，拿到回归证据再改 `pyproject.toml`——不要在主环境直接 `uv add deepagents` 触发连带升级；
2. **抬升范围评估**：`langchain 1.0.x → 1.3.x` 属 minor 抬升，重点回归 `app/services/llm/`（`bind_tools` / `with_structured_output` 行为）与 `app/core/langgraph/`（`astream` 语义、`RetryPolicy`）；`langchain-anthropic <1.1 → ≥1.5.4` 跨度较大，重点验证 prompt caching 中间件（`AnthropicPromptCachingMiddleware` 来自该包）与现有消息格式处理（`process_llm_response`）；
3. **替代路径**：若评估结论是不抬升，可只借鉴 deepagents 的设计（`DeltaChannel` reducer、skills 渐进披露、backend 协议）在手写图上自实现，规避全家桶升级风险——这也是本文档定位为「调研」而非「引入决策」的原因。

## 6. 二次开发检查清单

动手前逐项核对（对应 `create_deep_agent` 参数表见 [08 章](./08-API参考.md)）：

- [ ] **显式传 `model`**：`"provider:model"` 字符串或实例；绝不依赖 `model=None` 默认模型（`0.5.3` 弃用、`1.0.0` 移除）；
- [ ] **生产必传 `checkpointer`**：多轮记忆与 HITL 均依赖它；`StoreBackend` 场景同时传 `store`；
- [ ] **显式声明 `permissions` / `interrupt_on`**：默认全放行；`write_file` / `edit_file` / `delete`（0.7.0+）属写面，敏感目录补 `deny` / `interrupt` 规则；注意 0.7.0 起既有写放行规则同样授权递归 `delete`；
- [ ] **不引用 `BASE_AGENT_PROMPT`**（`0.7.0` 弃用、`0.9.0` 移除）；需要行为指引自己写 `system_prompt` 或注册 `HarnessProfile.base_system_prompt`；
- [ ] **不演示/依赖 `write_todos`**：`TodoListMiddleware` 0.7.0 起默认不装配；
- [ ] 自定义 state 继承 `DeepAgentState`（保住 `DeltaChannel`），私有字段标 `PrivateStateAttr`；
- [ ] 自定义中间件别与内置项撞 `.name`（撞了即原位替换）；不要试图排除 `FilesystemMiddleware` / `SubAgentMiddleware`（`ValueError`）；
- [ ] 重试/回退在传入前解决（`with_retry` / `with_fallbacks`、tenacity 中间件或 `LLMService` 供给），不期待 SDK 兜底；
- [ ] tracing callbacks 经 `config` 透传，子代理自动继承；

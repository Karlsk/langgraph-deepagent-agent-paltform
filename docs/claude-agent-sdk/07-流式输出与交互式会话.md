## 1. 消息类型族全表

出处：`src/claude_agent_sdk/types.py`、官方文档 <https://code.claude.com/docs/en/agent-sdk/python>（Message Types 节）。

| 类型 | 关键字段 / 语义 |
|---|---|
| `SystemMessage` | `subtype` + `data: dict`；`subtype="init"` 携带会话元数据（session_id、模型、工具清单）、各 MCP server 状态与已加载 skills |
| `AssistantMessage` | `content: list[ContentBlock]`，另有 `model` / `usage` / `stop_reason` / `session_id` / `parent_tool_use_id`（子代理归因） |
| `UserMessage` | `content: str \| list[ContentBlock]`；工具结果以 `ToolResultBlock` 经 UserMessage 回注（`tool_use_result` / `parent_tool_use_id`） |
| `ResultMessage` | **终态**：`subtype` ∈ `success` / `error_during_execution` / `error_max_turns` / `error_max_budget_usd` / `error_max_structured_output_retries`；携带 `duration_ms` / `is_error` / `num_turns` / `total_cost_usd` / `usage` / `result` / `structured_output` / `model_usage` |
| `StreamEvent` | token 级增量（包装原始 Anthropic API 流事件）；仅 `include_partial_messages=True` 时产出 |
| `RateLimitEvent` | 限流状态迁移（`allowed` → `allowed_warning` → `rejected`），携带 `RateLimitInfo` |
| `TaskStartedMessage` / `TaskProgressMessage` / `TaskUpdatedMessage` / `TaskNotificationMessage` | 后台任务生命周期（后台 Bash、Monitor、子代理等）；`TaskNotificationStatus` ∈ `completed` / `failed` / `stopped` |
| `HookEventMessage` | hooks 生命周期事件；仅 `include_hook_events=True` 时进入消息流（出处：`ClaudeAgentOptions.include_hook_events` 字段说明） |

消息流形态：首条通常是 `SystemMessage(init)`，中间 `AssistantMessage` 与 `UserMessage`（工具结果）交替，**末条恒为 `ResultMessage`**（出处：`src/claude_agent_sdk/client.py::receive_response` docstring）。`Message` 联合类型即上述各型的并集（出处：`src/claude_agent_sdk/types.py::Message`）。

## 2. 内容块（Content blocks）

出处：`src/claude_agent_sdk/types.py`、官方文档 <https://code.claude.com/docs/en/agent-sdk/python>（Content Block Types 节）。

| 块类型 | 字段 | 说明 |
|---|---|---|
| `TextBlock` | `text` | 文本输出 |
| `ThinkingBlock` | `thinking`、`signature` | 扩展思考内容（支持的模型） |
| `ToolUseBlock` | `id`、`name`、`input` | 工具调用请求 |
| `ToolResultBlock` | `tool_use_id`、`content`、`is_error` | 工具执行结果 |
| `ServerToolUseBlock` / `ServerToolResultBlock` | — | CLI 内置服务端工具（如 Web 搜索）对应块 |

`ContentBlock = TextBlock | ThinkingBlock | ToolUseBlock | ToolResultBlock`。

## 3. token 级流式：StreamEvent

出处：官方文档 <https://code.claude.com/docs/en/agent-sdk/streaming-output>。

默认情况下 SDK 只在每轮生成完毕后产出完整 `AssistantMessage`；设置 `include_partial_messages=True` 后额外产出 `StreamEvent`——**包装原始 Anthropic API 流事件的薄壳**（不是累积文本，需宿主自行累积）：

```python
from claude_agent_sdk.types import StreamEvent

async for message in client.receive_messages():
    if isinstance(message, StreamEvent):
        event = message.event  # 原始 API 流事件 dict
        if event.get("type") == "content_block_delta":
            delta = event.get("delta", {})
            if delta.get("type") == "text_delta":
                yield delta.get("text", "")      # 文本增量
            elif delta.get("type") == "input_json_delta":
                ...                               # 工具入参增量
```

常见原始事件：`message_start` / `content_block_start` / `content_block_delta`（`text_delta`、`input_json_delta`）/ `content_block_stop` / `message_delta` / `message_stop`（出处：官方 streaming-output 页）。

> ⚠️ **归因限制**：`StreamEvent` 仅来自主会话；**子代理的 token 级 delta 不转发**（`parent_tool_use_id` 恒为 `None`）。子代理输出归因须用完整消息上的 `parent_tool_use_id`（出处：官方 streaming-output 页）。

## 4. 迭代纪律：禁止提前 break

> ⚠️ **官方警告**：迭代消息流时**避免用 `break` 提前退出**——会导致 asyncio 清理问题；应让迭代自然走完，或用标志位记录「已拿到所需内容」（出处：官方文档 <https://code.claude.com/docs/en/agent-sdk/python>：*avoid using `break` to exit early as this can cause asyncio cleanup issues*）。
>
> 背景：`ResultMessage` 之后仍可能有尾随系统事件；拿到 result 就 `break` 会截断这些事件并破坏底层任务清理。

补充错误语义（出处：官方文档 <https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode>）：单次 `query()` 在收到 **error result**（如 `error_max_turns`）后，会先产出该 result 消息再 **raise**——宿主须用 try 块包裹循环才能继续后续逻辑。

## 5. 输入模式：streaming input vs single-message

出处：官方文档 <https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode>、`src/claude_agent_sdk/query.py` docstring。

| 维度 | streaming input | single-message |
|---|---|---|
| prompt 形态 | `AsyncIterable[dict]`，每条形如 `{"type": "user", "message": {"role": "user", "content": ...}, "parent_tool_use_id": ..., "session_id": ...}` | `str` |
| 图片附件 | ✅ 支持 | ❌ 不支持 |
| 消息排队 | ✅ 多条顺序排队 | ❌ |
| 实时中断 | ✅ `interrupt()` | ❌ |
| 多轮会话 | ✅ 会话常驻、上下文自然延续 | 受限（需靠 resume 拼接） |
| 典型场景 | 聊天应用、REPL、需按响应决定下一步输入 | 一次性问答、批处理、无状态环境（如 lambda） |

**`ClaudeSDKClient` 双向流方法面**（出处：`src/claude_agent_sdk/client.py`、官方文档 <https://code.claude.com/docs/en/agent-sdk/python> Methods 节）：`connect()` / `disconnect()`、`query()`、`receive_messages()` / `receive_response()`（后者迭代到 `ResultMessage` 为止）、`interrupt()`、`set_permission_mode()`、`set_model()`、`rewind_files()`、`get_mcp_status()` / `reconnect_mcp_server()` / `toggle_mcp_server()`、`stop_task()`、`get_context_usage()`、`get_server_info()`；支持 `async with` 上下文管理。完整方法签名见 [08-API参考.md](./08-API参考.md)。

完整示例见 [`examples/07_interactive_client.py`](./examples/07_interactive_client.py)（sessions 见 [`examples/08_sessions_resume_fork.py`](./examples/08_sessions_resume_fork.py)）。

## 6. 已知坑：输入生成器异常静默卡死

出处：官方文档 <https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode>（Note 节）。

- **Python 侧**：streaming input 的消息生成器抛异常时，**只打 debug 级日志、不向外 raise**，会话会**静默卡死**（无输出、无报错）。排查手段：开启 debug 日志，优先检查生成器自身代码。
- 对照 TypeScript 侧的同类坑：生成器异常会让流以 `Claude Code process aborted by user` 结束，掩盖原始错误。

## 7. 会话控制与持久化（sessions）

出处：官方文档 <https://code.claude.com/docs/en/agent-sdk/sessions>、<https://code.claude.com/docs/en/agent-sdk/session-storage>、`src/claude_agent_sdk/__init__.py`（公共导出）。

**Options 侧会话控制字段**（出处：`src/claude_agent_sdk/types.py::ClaudeAgentOptions`）：

| 字段 | 语义 |
|---|---|
| `continue_conversation=True` | 继续当前目录下最近一次会话 |
| `resume="<session_id>"` | 按 session id 恢复 |
| `fork_session=True` | 配合 `resume` 时分叉为新 session（不续写原会话） |
| `session_id="<uuid>"` | 指定 session id（必须为合法 UUID；不能与 `continue_conversation`/`resume` 同用，除非同时设 `fork_session`） |

**transcript 存储位置**：`~/.claude/projects/<encoded-cwd>/*.jsonl`（设置 `CLAUDE_CONFIG_DIR` 时为其下同名结构）；`<encoded-cwd>` 是绝对路径中所有非字母数字字符替换为 `-`，如 `/Users/me/proj` → `-Users-me-proj`（出处：官方 sessions 页）。

**模块级会话函数**（同步读本地 transcript，出处：`src/claude_agent_sdk/__init__.py`）：`list_sessions()` / `get_session_info()` / `get_session_messages()` / `list_subagents()` / `get_subagent_messages()`；变更类：`rename_session()` / `tag_session()` / `delete_session()` / `fork_session()`（返回 `ForkSessionResult`）。

**`SessionStore` 协议**（外部存储镜像，出处：官方文档 <https://code.claude.com/docs/en/agent-sdk/session-storage>）：通过 `ClaudeAgentOptions.session_store`（配 `session_store_flush="batched"|"eager"`、`load_timeout_ms`）把 transcript 镜像到外部后端，使**任意主机都能 resume**——适合 CI / 无服务器 / 多副本场景，可对接 PostgreSQL / S3 / Redis 等；另有 `*_from_store` / `*_via_store` 系列异步变体与 `InMemorySessionStore` 参考实现（出处：`src/claude_agent_sdk/__init__.py` 导出清单）。

## 8. FastAPI SSE 对接模式

本节给出 claude-agent-sdk 消息流 → FastAPI SSE 帧的对接要点，**蓝本为本项目既有实现** `app/api/v1/chatbot.py`（`event_generator` + `StreamingResponse`）。

### 8.1 本项目蓝本回顾

`chat_stream` 端点的模式（出处：`app/api/v1/chatbot.py`）：

```python
async def event_generator():
    try:
        async for chunk in agent.get_stream_response(...):
            response = StreamResponse(content=chunk, done=False)
            yield f"data: {json.dumps(response.model_dump(mode='json'))}\n\n"
        final_response = StreamResponse(content="", done=True)   # 收尾帧
        yield f"data: {json.dumps(final_response.model_dump(mode='json'))}\n\n"
    except Exception as e:
        logger.exception("stream_chat_request_failed", session_id=session.id, error=str(e))
        yield f"data: {json.dumps(StreamResponse(content=str(e), done=True).model_dump(mode='json'))}\n\n"

return StreamingResponse(event_generator(), media_type="text/event-stream")
```

要点：端点带 `@limiter.limit(...)` 限流装饰器、structlog `logger.exception` 记录失败、错误也走 SSE 帧而非中断连接、结尾恒有 `done=True` 帧。

### 8.2 SDK 侧对接要点

把 `agent.get_stream_response(...)` 换成 SDK 消息流即可同构迁移：

- **帧来源**：`ClaudeSDKClient` 场景用 `await client.query(prompt)` + `async for message in client.receive_response()`；一次性场景直接迭代 `query(prompt=..., options=...)`。每帧把 `Message` 序列化（建议按类型裁剪字段）后以 `data: {...}\n\n` 发出。
- **partial events 帧合并**：`StreamEvent` 粒度是 token 级，逐 delta 发帧会产生海量小帧；建议在宿主侧累积 `text_delta`，按阈值（字符数或时间窗）合并成帧后再 yield，完整 `AssistantMessage` / `ResultMessage` 仍照常发整帧。
- **客户端断连清理**：SSE 生成器被 Starlette 取消时（客户端断开），应在 `finally` 中执行 `await client.interrupt()`（停止当前轮）与 `await client.disconnect()`（回收 CLI 子进程）；复用型注册表场景至少 `interrupt()`，进程回收交给空闲回收策略（见 [01 章第 4 节](./01-架构总览与运行时数据流.md#4-fastapi-宿主并发会话模式)）。
- **迭代纪律**：生成器内不得在 `ResultMessage` 后 `break`（第 4 节）；`receive_response()` 本身迭代到 result 即自然结束，是 SSE 场景的推荐 API。
- **背压**：SDK 与 CLI 子进程之间的缓冲走 anyio 异步流（`max_buffer_size` 约束 CLI stdout 缓冲上限，出处：官方 `/agent-sdk/python` 参考页）；慢速 SSE 消费者会经由异步迭代自然形成背压，无需宿主另建队列，但要避免在生成器里做重活阻塞消费。
- **错误语义**：`query()` 在 error result 后 raise（第 4 节），SSE 生成器须像本项目蓝本一样 try/except 包住迭代，把异常转成错误帧发给前端。

完整示例见 [`examples/06_streaming.py`](./examples/06_streaming.py)（token 级流式）与 [`examples/09_fastapi_sse_integration.py`](./examples/09_fastapi_sse_integration.py)（SSE 集成骨架）。

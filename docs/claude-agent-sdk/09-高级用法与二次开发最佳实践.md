## 2. hooks 实战：短路、改写与注入

hooks 在 `query()` 与 `ClaudeSDKClient` 中**均可用**（0.2.135 中两者共用 `_internal/client.py::_process_query_inner`，内部恒 streaming mode，控制通道恒建立；唯一真实约束：`can_use_tool` 搭配字符串 prompt 会 raise。出处：`src/claude_agent_sdk/_internal/client.py`、[06 章 §2.3](./06-MCP集成.md#23-可用性事实与真实约束02135-核实)）。`ClaudeSDKClient` 的选型价值在多轮对话与 `interrupt()` / `set_model()` 等交互能力（见 [01 章第 2 节](./01-架构总览与运行时数据流.md#2-双-apiquery-vs-claudesdkclient-选型)）。完整类型速查见 [08 章第 6 节](./08-API参考.md#6-hooks-类型)，可运行示例见 `examples/07_interactive_client.py`。

### 2.1 PreToolUse 短路决策优先级

`PreToolUse` hook 经 `hookSpecificOutput.permissionDecision` 返回决策，短路优先级为：

```text
deny   ── 直接拒绝该次工具调用（最强短路；reason 经 permissionDecisionReason 反馈给 Claude）
defer  ── hook 不决策，交回后续权限流（settings 规则 → permission_mode → can_use_tool）
ask    ── 落到确认环节（can_use_tool 回调 / 权限提示）
allow  ── 放行；但 ⚠️ allow 不跳过后续 deny / ask 规则评估（见 08 章 §7.1 第 ① 步注记）
```

出处：官方 Python 参考页 Hook Types 节（`PreToolUseHookSpecificOutput`）、[08 章 §6.3、§7.1](./08-API参考.md#63-输出-hookjsonoutput)。要点：

- **deny 是唯一「一锤定音」的 hook 决策**；allow 只是「不拦截」，硬性封禁请用 `disallowed_tools`（第 3 节）。
- 多个 matcher 的 hook 同时命中时按序执行，任一返回 deny 即短路。

### 2.2 入参改写与上下文注入

| 能力 | 字段 | 事件 | 典型用法 |
|---|---|---|---|
| 改写工具入参 | `hookSpecificOutput.updatedInput` | `PreToolUse` | 强制给 `Bash` 命令加前缀、抹去入参中的敏感字段 |
| 注入补充上下文 | `hookSpecificOutput.additionalContext` | `PreToolUse` / `PostToolUse` / `UserPromptSubmit` / `SubagentStart` / `PostToolUseFailure` | 向 Claude 追加审计提示、合规约束 |
| 改写工具输出 | `hookSpecificOutput.updatedToolOutput` | `PostToolUse` | 脱敏后再回注（`updatedMCPToolOutput` 已弃用） |

出处：官方 `/agent-sdk/python` 参考页 Hook Types 节、[08 章 §6.3](./08-API参考.md#63-输出-hookjsonoutput)。

### 2.3 HookMatcher 与 timeout

`HookMatcher(matcher=..., hooks=[...], timeout=...)`：`matcher` 为工具名模式（如 `"Bash"`、`"Write|Edit"`，`None` = 匹配全部）；`timeout` 单位秒，省略用事件默认值（多数事件 600 秒、`UserPromptSubmit` 30 秒）。**重活别放 hook**：超时会阻塞对应工具调用（出处：[08 章 §6.2](./08-API参考.md#62-回调签名与-hookmatcher)）。

## 3. permissions 六步序要点与 bypassPermissions 风险

完整六步评估序见 [08 章 §7.1](./08-API参考.md#71-六步评估序)（出处：官方 permissions 页）。二开只需记住四条：

1. **hooks 在最前（第 ① 步）**：deny 可一票否决；allow 不豁免后续步骤。
2. **`disallowed_tools` 是唯一的硬封禁**：第 ② 步在**所有权限模式（含 `bypassPermissions`）下生效**；裸名 deny 直接把工具移出上下文，作用域规则（如 `"Bash(rm *)"`）逐次拦截匹配调用。
3. **`allowed_tools` 不是白名单**：未列出的工具落到权限流而非直接拒绝；无人值守场景配 `permission_mode="dontAsk"` 让未预批准者直接拒绝（见 [05 章第 4 节](./05-Skill系统.md#4-警示上下文过滤器--沙箱)）。
4. **⚠️ `bypassPermissions` 会旁路 `allowed_tools` 语义**：到达第 ④ 步的调用一律放行，`allowed_tools` 不再起把关作用。因此**一旦使用 bypass，必须同时用 `disallowed_tools` 列出封禁清单**，否则等于全放行（出处：官方 permissions 页、[08 章 §7.1 警示框](./08-API参考.md#71-六步评估序)）。

> 服务端/多租户场景的推荐基线：`permission_mode="dontAsk"` + 精确 `allowed_tools` + `disallowed_tools` 兜底；`can_use_tool` 回调只承接真正的动态策略（如按路径白名单放行 Write）。

## 4. 多租户 prompt-cache 策略

出处：官方 modifying-system-prompts 页「Improve prompt caching across users and machines」节、[03 章第 3 节](./03-System-Prompt系统.md#3-preset-定制append-与-exclude_dynamic_sectionsprompt-cache)。

- **`exclude_dynamic_sections=True`**（preset 形态，Python SDK `>=0.1.58`）：把每会话动态段落（cwd、git 标志、auto-memory 路径、平台）从 system prompt 移入首条 user message，使 system prompt 前缀对**所有租户一致**，显著提升跨用户/跨机器 prompt cache 命中率。
- **定制一律走统一 `append`**：不要在 append 里拼接租户标识/动态变量——那会重新打碎缓存前缀。租户差异走 user message（如 `additionalContext`）或 CLAUDE.md（注入会话上下文，不碰 system prompt，见 [03 章 §4.2](./03-System-Prompt系统.md#4-setting_sourcesclaudemd-与-output-styles)）。
- 组合配方：`system_prompt={"type": "preset", "preset": "claude_code", "append": "<静态产品规则>", "exclude_dynamic_sections": True}`。

## 5. 成本治理

出处：[02 章第 5 节](./02-LLM集成与成本控制.md#5-成本控制与用量观测)、官方 cost-tracking 页 <https://code.claude.com/docs/en/agent-sdk/cost-tracking>。

| 手段 | 定位 |
|---|---|
| `max_turns` | 轮数闸：防工具循环失控（并发子代理场景同时设 `AgentDefinition.maxTurns`） |
| `max_budget_usd` | 美元闸：**客户端成本估算**达到即停（产出 `error_max_budget_usd`）；非 API 计费口径，做硬闸须留余量 |
| `task_budget` | API 侧 token 预算（beta），传 `{"total": <int>}` |
| `ResultMessage.total_cost_usd` / `usage` / `model_usage` | 按会话持久化做账的唯一数据源；示例见 `examples/06_streaming.py` |

> 宿主超时预算提醒：最坏墙钟耗时 ≈ `API_TIMEOUT_MS × (CLAUDE_CODE_MAX_RETRIES + 1) + backoff`（[02 章第 2 节](./02-LLM集成与成本控制.md#2-重试与超时python-层无重试-api)），HTTP 超时与 SLA 按此留余量。

## 6. 本项目二次开发落地建议

### 6.1 与既有模块的关系

| 本项目模块 | 与 claude-agent-sdk 的关系 |
|---|---|
| `app/core/langgraph/` | **定位互补而非替代**：LangGraph 负责本项目可编排、可 checkpoint 的确定性工作流；claude-agent-sdk 是「子进程里的自主编码 agent」。集成时把它当一个**黑盒 agent 节点**调用（消息流入/流出），不要把两者编排逻辑互相嵌套 |
| `app/services/llm/`（模型注册表） | **不适用**：SDK 的模型选择是传给 CLI 的字符串（`model` / `fallback_model`，见 [02 章第 1 节](./02-LLM集成与成本控制.md#1-模型选择别名完整-id-与回退模型)），不经过本项目 LLM service；重试同理只能经 `env` 注入（02 章第 2 节） |
| Langfuse tracing | **LLM 调用发生在 CLI 子进程内，langchain 回调包不到**。透传思路：宿主侧以一次 `query()`/轮次为一个 span，经 hooks（`PreToolUse`/`PostToolUse`）采集工具事件、以 `ResultMessage` 的 usage/cost 字段收尾，上报为 Langfuse generation/span；CLI 侧遥测能力另行以官方 monitoring 文档复核（落地前实测） |
| `AsyncPostgresSaver`（LangGraph checkpoint） | **思路可复用、实例不通用**：SDK 的会话持久化走 `SessionStore` 协议（`session_store` / `session_store_flush` / `load_timeout_ms`，`load()` / `list_subkeys()` 见 [08 章 §3.4](./08-API参考.md#34-会话控制)）。可基于本项目既有 PostgreSQL 连接池（`app/core/database.py`）实现 `SessionStore` 后端，达成跨主机 resume；SDK 自带 `InMemorySessionStore` 参考实现（[07 章第 7 节](./07-流式输出与交互式会话.md#7-会话控制与持久化sessions)） |

### 6.2 依赖抬升评估

出处：[README.md 第 6 节](./README.md#6-本地依赖速查)、[01 章](./01-架构总览与运行时数据流.md)。

- **新增 `mcp>=1.23,<2.0`**：本项目锁文件尚无 `mcp`，引入前用 `uv lock` 评估传递依赖面（无版本冲突结论见 README §6，但依赖面以实际 lock diff 为准）。
- **平台 wheel 与捆绑 CLI**：wheel 内捆绑原生 Claude Code CLI（`>=2.0.0`），**Docker 基础镜像须覆盖对应平台的 wheel**，且容器内允许 spawn 子进程、可写 `~/.claude`（transcript 落盘目录）。
- **CLI 子进程运行时要求**：日志必须路由 stderr（SDK `stderr` 回调承接）、结构化 JSON 只走 stdout——与本项目既有 CLI 结构化输出纪律一致；`ANTHROPIC_API_KEY` 须宿主显式注入（SDK 不读 `.env`）。

### 6.3 集成形态建议

参照 [01 章第 4 节](./01-架构总览与运行时数据流.md#4-fastapi-宿主并发会话模式) 与 [07 章第 8 节](./07-流式输出与交互式会话.md#8-fastapi-sse-对接模式)：多租户 Web 场景用**常驻 `ClaudeSDKClient` 注册表 + 空闲回收**，SSE 帧协议对齐本项目 `app/api/v1/chatbot.py`（错误走帧、结尾恒有 done 帧）；可运行骨架见 `examples/09_fastapi_sse_integration.py`。

## 7. 二次开发 checklist

- [ ] 独立 venv 验证 `examples/` 全部示例后，再评估纳入 `pyproject.toml`（README §6 纪律）。
- [ ] 锁定 `claude-agent-sdk` 版本；订阅 GitHub CHANGELOG（近乎每日发版，第 1.7 条）。
- [ ] 显式 `model`（勿依赖 CLI 默认）+ `fallback_model`；重试/超时经 `env` 注入并按第 5 节公式预留宿主超时预算。
- [ ] 成本三闸：`max_turns` + `max_budget_usd` + 持久化 `ResultMessage` 用量做账。
- [ ] 权限基线：`dontAsk` + 精确 `allowed_tools` + `disallowed_tools` 硬封禁；`bypassPermissions` 必须伴随封禁清单（第 3 节）。
- [ ] 多租户：preset + `exclude_dynamic_sections=True` + 静态 `append`（第 4 节）。
- [ ] 会话持久化：本机 transcript 起步；跨主机 resume 实现 PostgreSQL 后端 `SessionStore`（第 6.1 节）。
- [ ] 可观测：hooks 采集 + `ResultMessage` 收尾上报 Langfuse；CLI stderr 经 `stderr` 回调入 structlog（第 6.1、6.2 节）。
- [ ] 引用外部资料前按第 1 节防坑表自查过时信息。

## 1. 安装

推荐 `uv`（本项目工具链一致）：

```bash
uv pip install claude-agent-sdk
```

或使用 pip：

```bash
pip install claude-agent-sdk
```

出处：官方文档 <https://code.claude.com/docs/en/agent-sdk/quickstart>。

环境要求（出处：PyPI `claude-agent-sdk 0.2.135` 元数据）：

| 项 | 要求 |
|---|---|
| Python | `>=3.10` |
| 运行时依赖 | `anyio>=4.0`、`mcp>=1.23,<2.0`、`sniffio` |
| Claude Code CLI | `>=2.0.0`（出处：`src/claude_agent_sdk/_internal/transport/subprocess_cli.py::MINIMUM_CLAUDE_CODE_VERSION`） |

## 2. 捆绑原生 CLI 机制三态

Claude Agent SDK 是**薄层封装**：`query()` / `ClaudeSDKClient` 经内部 `SubprocessCLITransport` spawn 一个 Claude Code CLI 原生二进制子进程，stdin/stdout 走 NDJSON（stream-json）协议；**LLM 调用发生在 CLI 侧，不在 SDK 进程内**（出处：`src/claude_agent_sdk/_internal/transport/subprocess_cli.py`、官方文档 <https://code.claude.com/docs/en/agent-sdk/overview>）。

安装形态与 Node.js 依赖分三态：

| 态 | 场景 | Node.js 是否必需 |
|---|---|---|
| ① wheel（默认） | PyPI wheel 捆绑原生 Claude Code CLI 二进制，安装即用 | ❌ 不需要 |
| ② sdist / 无 wheel 平台 | 无捆绑二进制，须**另装 Claude Code CLI** 并保证其可执行文件在 `PATH` 中 | 视 CLI 安装方式而定 |
| ③ 运行 `npx` 类 stdio MCP server | 即便 SDK 本身不需要 Node，此类 MCP server 的启动仍依赖 Node 环境 | ✅ 需要 |

出处：官方文档 <https://code.claude.com/docs/en/agent-sdk/python>（安装与原生二进制说明）。

补充两点：

- `ClaudeAgentOptions.cli_path` 可指向**自定义 CLI 可执行文件**（例如自构建的 Claude Code 或替代实现），用于接管子进程入口（出处：`src/claude_agent_sdk/types.py::ClaudeAgentOptions`）。
- CLI 版本低于 `2.0.0` 时 SDK 会拒绝工作（出处同上 `MINIMUM_CLAUDE_CODE_VERSION`）。

## 3. 认证与环境变量

SDK 通过环境变量读取凭证，**不自动加载 `.env` 文件**——宿主应用须自行注入（本项目可由 Pydantic Settings / `scripts/set_env.sh` 承担）：

```bash
export ANTHROPIC_API_KEY=sk-ant-...   # 占位符，勿提交
```

网关替代方案（一句话）：亦支持经 AWS Bedrock、Google Vertex、Microsoft Foundry 网关调用，通过对应网关环境变量切换（出处：官方文档 <https://code.claude.com/docs/en/agent-sdk/overview> 的 provider 说明，详见后续 `02-LLM集成与成本控制.md`）。

> ⚠️ **禁止将真实密钥写入代码、文档或提交到仓库**（本项目红线，见 AGENTS.md：密钥一律 env，禁止硬编码）。
>
> ⚠️ **商业条款提示**：Anthropic 商业条款禁止第三方产品直接向用户提供 claude.ai 账号登录；面向用户的产品须使用 API key / 网关等凭证（出处：官方文档 <https://code.claude.com/docs/en/agent-sdk/overview> 认证节）。

## 4. 最小 quickstart

出处：`src/claude_agent_sdk/query.py::query`（签名与 docstring）、官方文档 <https://code.claude.com/docs/en/agent-sdk/quickstart>。

```python
import anyio

from claude_agent_sdk import ClaudeAgentOptions, query

async def main() -> None:
    options = ClaudeAgentOptions(model="claude-sonnet-4-5")  # 显式指定模型
    async for message in query(
        prompt="用三句话介绍 LangGraph。", options=options
    ):
        print(message)

anyio.run(main)
```

要点：

- **显式传 `model`**：避免依赖默认模型随版本漂移；`model` 亦接受 `None`（使用 CLI 默认模型），生产代码建议显式指定。
- `query()` 返回 `AsyncIterator[Message]`，逐条产出消息流；最后一个通常是携带用量与结果统计的 `ResultMessage`（消息类型族详见 [01 章第 5 节](./01-架构总览与运行时数据流.md#5-运行时数据流消息生命周期与异常族)）。
- `query()` 适合**一次性 / 单向**任务；需要多轮对话、`interrupt()` 等会话中控制时用 `ClaudeSDKClient`（hooks 与进程内自定义工具 `query()` 亦支持，不构成选型依据；选型对比见 [01 章第 2 节](./01-架构总览与运行时数据流.md#2-双-apiquery-vs-claudesdkclient-选型)）。
- 完整签名：`query(*, prompt: str | AsyncIterable[dict[str, Any]], options: ClaudeAgentOptions | None = None, transport: Transport | None = None) -> AsyncIterator[Message]`（出处：`src/claude_agent_sdk/query.py`）。

## 5. 与本项目的依赖关系与独立 venv 验证

**本项目 Python 3.13 满足 SDK 要求（`>=3.10`），无版本冲突；但 `mcp>=1.23,<2.0` 是本项目未引入的新依赖**，且 SDK 运行时会 spawn CLI 子进程。为不触碰 `pyproject.toml` 与现有锁文件，**所有示例在独立虚拟环境中验证**：

| 项 | 本项目现状 | SDK 要求 | 判定 |
|---|---|---|---|
| Python | 3.13 | `>=3.10` | ✅ 满足 |
| `anyio` | 已在锁文件 | `>=4.0` | ✅ 兼容 |
| `sniffio` | 已在锁文件 | 无下限要求 | ✅ 兼容 |
| `mcp` | 未引入 | `>=1.23,<2.0` | ⚠️ 新增依赖 |
| Claude Code CLI | 无 | 捆绑于 wheel（`>=2.0.0`） | ⚠️ 新增子进程运行时 |

**独立 venv 验证步骤**（不触碰本项目主依赖）：

```bash
# 在仓库外或 .gitignore 覆盖的目录下创建隔离环境
mkdir -p /tmp/claude-agent-sdk-poc && cd /tmp/claude-agent-sdk-poc
uv venv --python 3.13
source .venv/bin/activate
uv pip install "claude-agent-sdk==0.2.135"
export ANTHROPIC_API_KEY=sk-ant-...   # 占位符，勿提交
```

> ⚠️ **CLI 日志走 stderr**：CLI 子进程的日志与 SDK 自身日志均不应混入 stdout 结构化输出；本项目若在 CLI 入口集成 SDK，须延续「日志路由至 stderr」的既有约定（见本项目 workflow CLI 的同类处理）。
>
> 集成路径评估（纳入主依赖 vs 独立服务部署、进程池管理、与 LangGraph 会话模型的映射）留待 `09-高级用法与二次开发最佳实践.md` 展开。

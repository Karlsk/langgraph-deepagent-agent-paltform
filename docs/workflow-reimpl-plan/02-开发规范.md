## 0 防跑偏红线（R1–R10）

### R1 · 范围红线：只实现 BaseNode / LLMNode / HTTPNode

**正确做法**

- `workflow_engine/nodes/` 下只允许出现：`__init__.py`、`base.py`、`factory.py`、`llm_node.py`、`http_node.py`。
- `NodeType` 精简为本期需要的集合（至少 `LLM`、`HTTP`），可为扩展保留注册机制（见 R4），但**不携带** 19 种领域枚举。
- 所有"听起来像业务"的需求（plan/worker/reflection/agent/merge/dispatcher/triage/…）一律记入"未来扩展"清单，本期不写一行相关代码。

```python
# ✅ 正例：workflow_engine/models.py 中的精简 NodeType
from enum import Enum
```

### R2 · 通用性红线：reducer 只来自 YAML 显式声明

**正确做法**

- `state.py` 的 `StateModelFactory.create_state_model(state_schema)` **只读取 `StateFieldSchema.reducer` 字段**来决定 channel 语义：
  - `reducer="add"` → `Annotated[list, operator.add]`
  - `reducer="last"` → `Annotated[T, _last]`（`def _last(a, b): return b`）
  - 未声明 reducer → LangGraph 默认 `LastValue`（后写覆盖），**不做任何特判**。
- 唯一允许的"自动行为"是**语义明确的 `history` 字段自动注入**：默认 `list` + `add` reducer，且**可被 YAML 显式声明覆盖**。该行为必须在 docstring 中写清楚并有测试。

```python
# ✅ 正例：state.py —— reducer 完全由 YAML 驱动
import operator
from typing import Annotated, Any


def _last(a: Any, b: Any) -> Any:
    """reducer="last"：后写覆盖。"""
    return b


def _reducer_for(field: StateFieldSchema) -> Any | None:
    if field.reducer == "add":
        return operator.add
    if field.reducer == "last":
        return _last
    if field.reducer is not None:
        raise ValueError(f"Unknown reducer: {field.reducer!r}")
    return None  # None -> LangGraph LastValue（后写覆盖）
```

**错误做法**

```python
# ❌ 反例：原 graph_builder.py create_state_model 对领域字段名写死特判
if field_name in ("circle_conclusions", "history"):
    annotation = Annotated[list, operator.add]
elif field_name in ("planner_result", "worker_result", "reflector_result",
                    "circle_meta", "circle_index", "step", "current_node"):
    annotation = Annotated[Any, _last]
```

**检查方法**：`grep -rn "circle_\|planner_result\|worker_result\|current_node" workflow_engine/state.py` 必须为空。

### R3 · 契约红线：节点进出契约 + 不可变 state

**正确做法**

- 节点唯一执行单元：`build_runnable()` 返回 `RunnableLambda(func).with_config(tags=[self.name])`。
- `func(state) -> dict`：先用 `convert_state_to_dict(state)` 把入参转成普通 dict（**只读使用**），业务处理后用 `map_output_to_state(self.name, output, state_dict)` 生成 state-update dict 并返回。
- 由 LangGraph 负责把 update dict 合并进 channel，节点**绝不**就地修改输入 state。

```python
# ✅ 正例：节点函数骨架
def _run(self, state: Any) -> dict[str, Any]:
    state_dict = convert_state_to_dict(state)     # 进：只读 dict
    output = self._do_work(state_dict)            # 业务，产出新 dict
    return map_output_to_state(self.name, output, state_dict)  # 出：update dict
```

**错误做法**

```python
# ❌ 反例：就地 mutate 输入 state / 自己拼 state 更新
def _run(self, state):
    state["llm_result"] = self._call_llm(state)   # 直接改输入对象
    state["history"].append("llm done")           # 就地改共享 list
    return state                                  # 把整个 state 返回去
```

**检查方法**：代码评审逐节点核对"convert_state_to_dict 进 / map_output_to_state 出"；单测断言"调用节点后原始输入对象未被修改"。

### R4 · 扩展红线：注册表优先，禁止 if/elif 堆叠

**正确做法**

- 新节点类型一律通过 `register_node_type(type_name, node_class)` 注册。
- `create_node(definition, operator_log=None)`：**先查插件注册表，再走内置分发**；本期内置分发只允许 `llm` / `http` 两个分支。
- 未知类型抛 `ValueError`，错误信息列出当前已注册类型，便于排障。

```python
# ✅ 正例：nodes/factory.py —— 注册表优先 + 极简内置分发
_NODE_REGISTRY: dict[str, type[BaseNode]] = {}


def register_node_type(type_name: str, node_class: type[BaseNode]) -> None:
    _NODE_REGISTRY[type_name] = node_class


def create_node(
    definition: NodeDefinition,
    operator_log: OperatorLog | None = None,
) -> BaseNode:
    if definition.type in _NODE_REGISTRY:
        return _NODE_REGISTRY[definition.type](
            definition.name, definition.type, definition.config, operator_log
        )
    raise ValueError(
        f"Unknown node type: {definition.type!r}. "
        f"Registered types: {sorted(_NODE_REGISTRY)}"
    )
```

**错误做法**

```python
# ❌ 反例：原 factory.py create_node 的 20 层 if/elif 领域分发
if node_type in ("plan", "Planner"):
    return PlannerNode(...)
elif node_type in ("worker", "Worker"):
    return WorkerNode(...)
elif node_type in ("device_work", "DeviceWork"):
    return DeviceWorkNode(...)
# ... 每加一种节点就要改工厂文件
```

**检查方法**：`factory.py` 全文不应出现 `PlannerNode/WorkerNode/DispatcherNode` 等任何领域节点名；内置兜底分支恰好 2 个（llm/http）。

### R5 · 安全红线：密钥 env-only，日志不落密

**正确做法**

- 所有密钥（API key、密码、token）只从环境变量读取；LLMNode 按 `llm_type` 解析对应 env（如 `OPENAI_API_KEY` / `ANTHROPIC_API_KEY`）。
- 仓库提供 `.env.example`（只有键名与占位说明，**无真值**）；`.env` 进 `.gitignore`。
- 日志走结构化 logger，并挂载脱敏过滤器（见第 9 章）；**禁止**把完整 state、密钥、完整请求/响应体打进日志。

```python
# ✅ 正例：nodes/llm_node.py —— 运行时从 env 解析密钥
import os


def _resolve_api_key(self) -> str:
    env_var = {"openai": "OPENAI_API_KEY", "anthropic": "ANTHROPIC_API_KEY"}[self.llm_config.llm_type]
    api_key = os.environ.get(env_var)
    if not api_key:
        raise ConfigError(f"Missing required env var: {env_var}")   # 异常族见 01 · 异常契约
    return api_key
```

**错误做法**

```python
# ❌ 反例一：原 YAML 配置里硬编码 API key（原代码多处）
config:
  api_key: "sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxx"

# ❌ 反例二：原 utils.py 给密钥塞 mock 兜底值，掩盖配置缺失
api_key = os.getenv("OPENAI_API_KEY") or "mock-key-for-initialization"

# ❌ 反例三：原路由闭包把完整 state print 到 stdout
print(f"[ROUTER DEBUG] source={source}, state={state_dict}")
```

**检查方法**：`grep -rniE "(api[_-]?key|secret|password|token)\s*[:=]\s*['\"][A-Za-z0-9]" workflow_engine/ tests/` 无真实密钥命中；日志脱敏有单测（第 9 章）。

### R6 · 错误红线：禁止死 try/except

**正确做法**

- 每个 `except` 必须显式处理：**记录（结构化日志）+ 重抛**，或由配置开关显式驱动的分支（如 `mock_enabled` 显式 mock 模式），择一并写清楚；**禁止**失败时返回硬编码兜底（不引入失败降级）。
- mock 路径（`mock_enabled` / `mock_responses`）**必须由配置开关显式启用**，且**有测试覆盖**；默认关闭；mock 未命中必须**显式报错**，不得静默回退真实调用。

```python
# ✅ 正例：HTTPNode 失败路径 —— 显式处理：记录 + 重抛（mock_enabled 是显式 mock 模式，不是失败降级）
try:
    data = self._send_request(rendered)
except httpx.HTTPError as exc:
    logger.error("http_node.request_failed", extra={"node": self.name, "error": str(exc)})
    raise HTTPNodeError(f"HTTP request failed: {exc}") from exc
```

**错误做法**

```python
# ❌ 反例一：静默吞错
try:
    data = self._send_request(rendered)
except Exception:
    pass                                          # 发生了什么？没人知道

# ❌ 反例二：原 WorkerNode 的"死异常兜底"（H2）——死 try/except：except 分支逻辑不可靠
#    且从未被测试覆盖；降级路径无配置开关、硬编码 mock 返回
except Exception as e:
    logger.error(...)                             # 分支逻辑不可靠，无测试覆盖
    return {"worker_result": "mock 设备信息..."}   # 且无开关硬编码 mock
```

**检查方法**：`ruff` 启用 `BLE`/`S110` 等规则辅助审查；对 LLM/HTTP 失败路径逐一写单测（mock 抛错，断言显式重抛与结构化记录）。对应 H2，验收在 Phase 4 / Phase 5。

### R7 · 质量红线：严格 TDD，覆盖率 ≥ 80%

**正确做法**

1. RED：先写失败测试（描述期望行为）。
2. GREEN：写**最小**实现让测试通过。
3. REFACTOR：在测试保护下重构。
4. 每个 Phase 交付前运行 `pytest --cov=workflow_engine --cov-report=term-missing --cov-fail-under=80`。

**错误做法**

- 一次性写完几百行实现再"补"测试（补出来的测试只会复述实现，抓不到回归）。
- 为凑覆盖率写无断言的测试（`def test_x(): foo()`）。

**检查方法**：CI 门禁 `--cov-fail-under=80`；评审时核对"测试先于实现"的提交顺序。

### R8 · 结构红线：小文件 / 小函数 / 单一职责

**正确做法**

- 单文件典型 200–400 行，**硬上限 400 行**；单函数 **< 50 行**；嵌套 **≤ 4 层**（多用提前返回）。
- 按领域/职责拆模块：`state.py`（状态模型合成）、`graph_builder.py`（图编译）、`registry.py`（运行时注册与执行）各司其职（落实 C1）。

```
❌ 反例：原 graph_builder.py 一个文件 814 行，混了三种职责：
   StateModelFactory（状态合成）+ GraphBuilder（图编译）+ WorkflowRegistry（运行时）
```

**检查方法**：`wc -l workflow_engine/**/*.py` 无超 400 行者；评审关注"这个函数能不能再拆"。

### R10 · 缓存红线：上限 + 失效 + 开关

**正确做法**

- 本期**默认不引入任何缓存**。
- 若未来 LLMNode/HTTPNode 确需缓存：必须有 `maxsize`（上限淘汰）+ TTL（失效）+ 显式配置开关（默认关）+ 文档，且 cache key 设计正确（覆盖所有影响输出的入参）。

**错误做法**

```python
# ❌ 反例：原 _subgraph_cache —— 模块级 dict，无上限、永不失效、
#    读无条件/写有条件，跨请求重放陈旧结果（H4）
_subgraph_cache: dict = {}


def get_or_build(key):
    if key in _subgraph_cache:
        return _subgraph_cache[key]
    ...
```

**检查方法**：全仓 `grep -rn "lru_cache\|cache" workflow_engine/` 逐处核对四要素（上限/TTL/开关/文档）；如实现缓存，测试命中/失效/上限淘汰。

- 容器用内建泛型：`dict[str, Any]`、`list[ExecutionLog]`，不再从 `typing` 导入 `Dict/List`。

## 3 Pydantic 与边界校验

### 3.1 总则

| 原则 | 落地 |
|---|---|
| 边界校验 | YAML → `WorkflowDefinition`；`NodeDefinition.config` → `LLMConfig`/`HTTPNodeConfig`；API 请求体 → 请求模型。进入系统第一关必须过模型 |
| Fail fast | 校验失败立即抛 `ValidationError`/`ValueError`，附带可读信息；禁止"带病运行到深处再 KeyError" |
| 不信任外部数据 | YAML、HTTP 响应、LLM 返回值都是"外部数据"，用前先校验/兜底取值 |
| v2 only | 全量 pydantic v2 API；禁止 v1 遗留写法 |

### 3.2 v2 写法对照

```python

from pydantic import BaseModel, ConfigDict, Field


class HTTPNodeConfig(BaseModel):
    """HTTP 节点配置（v2 写法）。"""

    model_config = ConfigDict(extra="forbid", frozen=True)   # 配置对象不可变 + 拒绝未知字段

    url: str = Field(min_length=1)
    method: Literal["GET", "POST", "PUT", "DELETE"] = "POST"
    headers: dict[str, str] | None = None
    body_template: str | None = None
    response_path: str | None = None                          # 点路径，如 "data.result"
    timeout: float = Field(default=30.0, gt=0)
    max_retries: int = Field(default=0, ge=0)                 # 默认不重试；重试必须显式开启
    retry_base_delay: float = Field(default=1.0, gt=0)        # 指数退避基础延迟（秒）
    retry_on_status: list[int] = Field(default_factory=lambda: [429, 500, 502, 503, 504])
    mock_enabled: bool = False                                # 显式开关，默认关（R6/H2）
    mock_responses: dict[str, str] | None = None              # key = "{METHOD} {url}"；未命中 → 显式报错
```

### 3.3 各类模型的 extra 策略（不要搞反）

| 模型类别 | extra 策略 | 理由 |
|---|---|---|
| **WorkflowDefinition**（DSL 根定义） | `extra="ignore"` | 容忍 YAML 里 `description` 等非模型字段（注释性键），行为由 `test_extra_yaml_keys_ignored` 锁定（K1） |
| **节点配置模型**（LLMConfig、HTTPNodeConfig 等） | `extra="forbid"` | 写错配置字段名必须立刻报错，而不是被静默忽略 |
| **动态状态模型**（`create_state_model` 产物） | `extra="allow"`（K2，Dify 风格） | 允许节点写未声明字段，state 可生长 |

## 4 不可变性与状态更新

### 4.1 核心规则（R3）

1. 节点的 `func(state)` 收到的是 LangGraph 传入的状态对象（动态 Pydantic 模型或 dict）。**只读**。
2. 第一件事：`state_dict = convert_state_to_dict(state)`。该函数语义（K9）：pydantic → `model_dump()`；dict → 直通；其它 → `{}`。
3. 业务逻辑只读 `state_dict`，产出**全新的** `output` dict。
4. 最后一件事：`return map_output_to_state(self.name, output, state_dict)`，由 LangGraph reducer 完成合并。
5. 配置对象（`LLMConfig`/`HTTPNodeConfig`）`frozen=True`；节点实例字段在 `build_runnable` 之后不得被执行路径改写。

### 4.2 map_output_to_state 语义（K9 + C4）

新实现必须满足且必须在 docstring 写清：

| 行为 | 语义 |
|---|---|
| 双写（dual_write，**默认开**，可配置关闭） | 同时写 `{node_name}_result` 整包 + 逐字段平铺到 state |
| history 自动追加（history_increment，**默认开**） | **仅当** state 中 `history` 是 `list`（对应 `reducer="add"` 的 list channel）且节点输出未自带 `history` 键时，对 history 只返回一条摘要**增量** `[entry]`，`entry = f"{node_name}: {str(node_output)[:100]}..."`；**add reducer 下禁止返回全量 history**（否则经 channel 合并后历史翻倍）；消除原代码 str/list 二义性（C4） |
| 纯函数 | 不修改任何入参，返回新 dict |

```python
# ✅ 正例：utils.py 新实现骨架
def map_output_to_state(
    node_name: str,
    node_output: dict[str, Any],
    state: dict[str, Any] | None = None,
    *,
    dual_write: bool = True,
    history_increment: bool = True,
) -> dict[str, Any]:
    """将节点输出映射为 LangGraph state-update dict。

    Args:
        node_name: 节点名。
        node_output: 节点业务输出（新 dict，不得复用输入对象）。
        state: 当前状态 dict（只读，用于判断 history 是否为 list channel）。
        dual_write: True 时同时写 {node_name}_result 整包与逐字段平铺；
            False 时只写 {node_name}_result 整包。
        history_increment: True（默认）时，若 history 是 add reducer 的 list channel
            且输出未自带 history，仅返回增量 [entry]。

    Returns:
        全新的 state-update dict。
    """
    update: dict[str, Any] = {f"{node_name}_result": node_output}
    if dual_write:
        update.update(node_output)

    if (
        history_increment
        and state
        and "history" in state
        and "history" not in node_output
        and isinstance(state["history"], list)   # 仅 list channel（reducer="add"）才追加
    ):
        entry = f"{node_name}: {str(node_output)[:100]}..."
        # ⚠️ add reducer 下禁止返回全量：channel 会自行合并，这里只返回增量 [entry]
        update["history"] = [entry]
    return update
```

```python
# ❌ 反例一：就地 append 共享 list（破坏不可变，并发下互相污染）
state["history"].append(entry)
return state

# ❌ 反例二：对 history 做 str 拼接（原代码二义性来源之一，C4）
update["history"] = str(history) + entry

# ❌ 反例三：add reducer 下返回全量 history（每次合并后历史翻倍，C4 bug 现场）
update["history"] = state["history"] + [entry]   # reducer 会把"全量"再叠加一次 → 翻倍
```

## 5 节点开发规范

### 5.1 BaseNode 契约（K4，必须原样沿用）

| 成员 | 契约 |
|---|---|
| `__init__(name, node_type, config, operator_log=None)` | 保存节点元信息；初始化 `_execution_history: list[ExecutionLog]` |
| `build_runnable() -> Runnable`（抽象） | **唯一执行单元**；返回 `RunnableLambda(func).with_config(tags=[self.name])`；`func(state) -> dict` |
| `wrap_runnable(func)`（工具方法） | 统一产出 `RunnableLambda(func).with_config(tags=[self.name])`，供子类 `build_runnable` 复用，集中保证 tags 契约 |
| `validate_config() -> bool`（抽象） | 配置非法时抛 `ValueError`（信息含节点名）；合法返回 True。必须在 `build_runnable` 开头调用 |
| `log_execution(execution_log)` | 追加一条 `ExecutionLog`：同时写实例历史**与**当前运行级收集器（ContextVar `_RUN_COLLECTOR`，若存在）；运行时权威日志来自运行级收集器而非实例历史（H1/H3） |
| `get_execution_history() -> list[ExecutionLog]` | 返回**副本** |
| `clear_execution_history()` | 清空（⚠️ 生产执行路径禁止跨请求调用它来"收集日志"，见 H1，Phase 7） |

### 5.2 标准节点骨架（新增任何节点都从这份骨架开始）

```python
# workflow_engine/nodes/http_node.py（示意骨架，完整实现见 Phase 5）
"""HTTP 节点：模板化 HTTP 调用。"""

import logging
import time
from typing import Any

import httpx
from langchain_core.runnables import Runnable

from ..models import ExecutionLog, NodeType, OperatorLog
from ..utils import convert_state_to_dict, map_output_to_state
from .base import BaseNode

logger = logging.getLogger(__name__)


class HTTPNode(BaseNode):
    """通用 HTTP 节点：占位符渲染 + 结果提取。"""

    def __init__(
        self,
        name: str,
        config: dict[str, Any],
        operator_log: OperatorLog | None = None,
    ) -> None:
        super().__init__(name, NodeType.HTTP, config, operator_log)
        self.node_config = HTTPNodeConfig.model_validate(config)   # 边界即校验（R9）

    def validate_config(self) -> bool:
        if not self.node_config.url:
            raise ValueError(f"HTTP '{self.name}': url is required")
        return True

    def build_runnable(self) -> Runnable:
        """构建 Runnable。func 遵循：convert_state_to_dict 进 / map_output_to_state 出。"""
        self.validate_config()

        def http_func(state: Any) -> dict[str, Any]:
            state_dict = convert_state_to_dict(state)
            start = time.perf_counter()
            try:
                output = self._execute(state_dict)          # mock_enabled 显式 mock 模式在内部处理；未命中即报错
            except httpx.HTTPError as exc:
                self._log_failure(state_dict, exc, start)
                raise HTTPNodeError(f"HTTP request failed: {exc}") from exc   # 显式重抛，无失败降级
            self._log_success(state_dict, output, start)
            return map_output_to_state(self.name, output, state_dict)

        return self.wrap_runnable(http_func)

    # ── 私有实现（每个 < 50 行）──────────────────────────────
    def _execute(self, state_dict: dict[str, Any]) -> dict[str, Any]: ...
    def _log_success(self, state_dict, output, start) -> None: ...
    def _log_failure(self, state_dict, exc, start) -> None: ...
```

## 6 工厂与注册规范

### 6.1 注册与分发（K5）

```python
# ✅ 正例：workflow_engine/nodes/factory.py
"""节点工厂 + 插件注册表。

内置节点类型：llm、http。
扩展节点类型通过 register_node_type() 注册，无需修改本文件（R4）。
"""

from ..models import NodeDefinition, OperatorLog
from .base import BaseNode

_NODE_REGISTRY: dict[str, type[BaseNode]] = {}


def register_node_type(type_name: str, node_class: type[BaseNode]) -> None:
    """注册节点类型。

    Args:
        type_name: 节点类型字符串，需与 WorkflowDefinition.nodes[].type 一致。
        node_class: BaseNode 子类。

    Example:
        register_node_type("http", HTTPNode)
    """
    if not (isinstance(node_class, type) and issubclass(node_class, BaseNode)):
        raise TypeError(f"node_class must be a BaseNode subclass, got {node_class!r}")
    _NODE_REGISTRY[type_name] = node_class


def create_node(
    definition: NodeDefinition,
    operator_log: OperatorLog | None = None,
) -> BaseNode:
    """统一节点工厂：先查注册表；未命中再走"恰好 2 个"内置兜底分支。

    未知类型抛 ValueError（附已注册清单）。
    """
    operator_log = operator_log or OperatorLog(
        node_name=definition.name, input_schema={}, output_schema={}
    )
    node_class = _NODE_REGISTRY.get(definition.type)
    if node_class is not None:
        return node_class(definition.name, definition.config, operator_log)
    # 内置兜底分支（恰好 2 个）：大小写集合同兼 llm/http 别名兼容，不另设 validator
    if definition.type in ("llm", "LLM"):
        return LLMNode(definition.name, definition.config, operator_log)
    if definition.type in ("http", "HTTP"):
        return HTTPNode(definition.name, definition.config, operator_log)
    raise ValueError(
        f"Unknown node type: {definition.type!r}. "
        f"Use register_node_type() to add custom node types. "
        f"Registered types: {sorted(_NODE_REGISTRY)}"
    )
```

### 6.2 内置接线位置

### 7.1 状态模型

|---|---|

```python
# ✅ 正例：state.py 合成注解
from typing import Annotated, Any
import operator


def _last(a: Any, b: Any) -> Any:
    return b


TYPE_MAP: dict[str, Any] = {"str": str, "int": int, "float": float, "bool": bool, "list": list, "dict": dict}


def _annotation_for(field: StateFieldSchema) -> Any:
    py_type = TYPE_MAP.get(field.type)
    if py_type is None:                               # fail fast：不静默回退 Any/str
        raise ValueError(
            f"Unsupported state field type: {field.type!r}. "
            f"Supported types: {sorted(TYPE_MAP)}"
        )
    if field.reducer == "add":
        return Annotated[list, operator.add]
    if field.reducer == "last":
        return Annotated[py_type, _last]
    return py_type                      # -> LangGraph LastValue
```

### 7.3 条件边路由器（K7 + C3）

**规则**：

1. `EdgeDefinition.condition` 是点路径表达式，支持等值比较（`"a.b == 'x'"`）与纯路径真值判断（`"a.b"`）。
2. 路由器编译为闭包 `router(state) -> str`，经 `graph.add_conditional_edges(source, router, path_map)` 接入。
3. 调试输出**一律 `logger.debug`**，禁止 `print`（C3）。
4. **"无条件命中"行为必须显式可配置**：要么 `raise`（默认，fail fast），要么走 YAML 中显式声明的 `default_edge`。**禁止**静默落到最后一条边（C3）。
5. 比较只求值 YAML 声明过的白名单表达式，**禁止 `eval` 任意字符串**（安全）。

```python
# ✅ 正例：graph_builder.py 条件路由器
def _build_router(self, source: str, cond_edges: list[EdgeDefinition]) -> Callable[[Any], str]:
    default = self._resolve_default_edge(source, cond_edges)   # None 表示"未命中即 raise"

    def router(state: Any) -> str:
        state_dict = convert_state_to_dict(state)
        for edge in cond_edges:
            if _eval_condition(edge.condition, state_dict):    # 白名单求值器，非 eval
                logger.debug("router.matched source=%s condition=%r target=%s",
                             source, edge.condition, edge.target)
                return edge.target
        if default is not None:
            logger.debug("router.default source=%s target=%s", source, default)
            return default
        raise ConditionNotMatchedError(
            f"No condition matched at {source!r} and no default_edge declared"
        )

    return router
```

## 8 错误处理规范

> 对应隐患 **H2**（死 try/except：except 分支逻辑不可靠且从未被测试覆盖；且降级路径无配置开关、硬编码 mock 返回，失败节点直接崩图或返回硬编码 mock）。

### 8.1 错误分层

| 层 | 错误类型 | 处理策略 |
|---|---|---|
| DSL 定义 / 配置校验 | `ValueError` / `ValidationError` | **fail fast**，构建期抛出，附节点名与字段 |
| 节点运行期：外部调用失败 | `LLMNodeError` / `HTTPNodeError`（01 · 异常契约） | 结构化日志记录 → **显式重抛**；mock 模式仅在 `mock_enabled` 显式开关下生效，未命中即报错 |
| 节点运行期：契约违反、状态非法 | `WorkflowEngineError` 族 / `ValueError` | 记录后重抛，让图失败可见 |
| 注册表 / 图编译 | `WorkflowNotFoundError` / `ConditionNotMatchedError` / `ValueError` | fail fast |

### 8.2 三条铁律

1. **禁止死 except**：`except: pass`、`except Exception: return {}` 这类无记录无决策的分支一律打回（ruff BLE 辅助）。
2. **except 分支必须可靠 + 有测试覆盖**——H2 的根因是死 try/except（except 分支逻辑不可靠且从未被测试覆盖）+ 降级路径无配置开关、硬编码 mock 返回。要求：节点模块顶部统一 `logger = logging.getLogger(__name__)`，且每个失败路径都有"被真实触发"的单测兜住。
3. **mock 必须显式开关 + 有测试**：mock 模式（`mock_enabled`）默认关闭、开关显式置于配置模型中，mock 未命中显式报错（不做失败降级）；测试矩阵必须包含"mock 启用 × 未命中 → 显式报错""mock 关闭 × 外部抛错 → 显式重抛"组合。

### 8.3 正反例

```python
# ✅ 正例：LLMNode 429 指数退避重试（Phase 4，扁平重试字段 max_retries / retry_base_delay）
def _invoke_with_retry(self, messages: list) -> str:
    last_exc: Exception | None = None
    for attempt in range(self.llm_config.max_retries + 1):
        try:
            response = self._get_llm_instance().invoke(messages)
            return str(response.content)
        except Exception as exc:                       # noqa: BLE001 —— 供应商异常类型不统一
            last_exc = exc
            if not _is_rate_limit(exc) or attempt == self.llm_config.max_retries:
                logger.error("llm_node.invoke_failed node=%s attempt=%d error=%s",
                             self.name, attempt, exc)
                raise
            wait = self.llm_config.retry_base_delay * (2 ** attempt)
            logger.warning("llm_node.rate_limited node=%s retry_in=%.1fs", self.name, wait)
            time.sleep(wait)
    raise RuntimeError("unreachable") from last_exc
```

## 9 日志规范

> 对应隐患 **H6** 与清理项 **C9**：原代码在路由闭包把完整 state `print` 到 stdout、节点异常时返回硬编码 mock、YAML 硬编码密钥。新实现：日志结构化 + 脱敏，禁止 print，禁止完整 state/密钥入日志。

### 9.1 基本规则

| 规则 | 说明 |

| 内容纪律 | **禁止**记录：完整 state、密钥/token、完整请求/响应体、个人隐私。只记录定位所需的最小字段 |

### 9.2 脱敏过滤器（RedactFilter，H6/C9）

```python
# ✅ 正例：workflow_engine/logging_conf.py（完整定义以 01 · Phase 0/8 接口契约为准）
"""结构化日志初始化 + 脱敏过滤器。"""

import logging
import re
from typing import Any

_SECRET_PATTERN = re.compile(
    r"(?i)(api[_-]?key|secret|token|password|authorization)\s*[:=]\s*\S+"
)
_REDACTED = "***REDACTED***"


def redact(data: Any, *, max_len: int = 500) -> Any:
    """递归脱敏：替换键值型密钥，截断超长字符串，防止完整 state 入日志。"""
    if isinstance(data, str):
        data = _SECRET_PATTERN.sub(_REDACTED, data)
        if len(data) > max_len:
            return data[:max_len] + "...(truncated)"
        return data
    if isinstance(data, dict):
        return {k: redact(v, max_len=max_len) for k, v in data.items()}
    if isinstance(data, (list, tuple)):
        return type(data)(redact(v, max_len=max_len) for v in data)
    return data


class RedactFilter(logging.Filter):
    """日志脱敏过滤器：委托 redact() 抹掉键值型密钥与超长内容。"""

    def filter(self, record: logging.LogRecord) -> bool:
        if isinstance(record.msg, str):
            record.msg = redact(record.msg)
        if record.args:
            record.args = tuple(redact(a) for a in record.args)
        return True


def setup_logging(level: str = "INFO", *, json_output: bool = False) -> None:
    """进程级日志初始化（幂等，入口调用一次）。

    Args:
        level: 日志级别字符串（INFO/DEBUG/...）。
        json_output: True 时输出 JSON 行（供日志采集系统消费）；本期默认文本。
    """
    handler = logging.StreamHandler()
    handler.setFormatter(logging.Formatter(
        "%(asctime)s %(levelname)s %(name)s %(message)s"
    ))
    handler.addFilter(RedactFilter())
    root = logging.getLogger()
    root.handlers.clear()
    root.addHandler(handler)
    root.setLevel(level.upper())
```

> 生产部署可置 `json_output=True` 输出 JSON 行（字段含 `timestamp/level/logger/message/extras`）；`redact` / `RedactFilter` / `SECRET_KEY_PATTERNS` 的完整口径以 01 · Phase 8 接口契约为准，本节为示意骨架，不强制引入第三方。

## 12 并发与缓存规范

### 12.1 并发（对应 H1 / H3，Phase 7 落地）

**隐患回顾**：原 Registry 是进程级单例、被 Web 线程池共享，但 `execute_workflow` 非原子；且通过 `node.clear_execution_history()` / `node._execution_history` 在**共享节点实例**上就地变更来收集日志——两个并发请求打同一 workflow_id 会互相清空/覆盖执行历史（H1）。

**规则**：

| 规则 | 落地 |
|---|---|
| 按 workflow_id 串行化 | 每个 workflow_id 一把 `threading.RLock`（可重入），`execute_workflow` 全程持锁 |
| 禁止跨请求 mutate 共享节点 | 生产执行路径**禁止**"clear → run → read `_execution_history`"这种在共享实例上就地变更的收集模式 |
| 运行级日志收集（H3） | 每次运行用 run-scoped `RunLogCollector`（`add(log)` / `collect()`），经 ContextVar `_RUN_COLLECTOR` 挂载（在 `nodes/base.py` 定义，由 registry 在 `execute_workflow` 进出场 set/reset）；`BaseNode.log_execution` 经 `get_run_collector().add(...)` 写收集器，覆盖"本次运行实际执行的所有节点"，与节点创建方式解耦（为未来子图预留） |
| 全局可变状态最小化 | 注册表内部三张映射（`_registry`/`_definitions`/`_nodes_map`）的增删一律持注册表级锁（C6/H7） |

```python
# ✅ 正例：registry.py —— 每 workflow 一把可重入锁 + ContextVar 运行级收集（H1/H3）
class WorkflowRegistry:
    def __init__(self) -> None:
        self._registry: dict[str, CompiledGraph] = {}
        self._definitions: dict[str, WorkflowDefinition] = {}
        self._nodes_map: dict[str, dict[str, BaseNode]] = {}
        self._run_locks: dict[str, threading.RLock] = {}
        self._meta_lock = threading.Lock()                    # 守护锁表创建

    def execute_workflow(self, workflow_id: str, input_data: dict[str, Any]) -> RunResult:
        lock = self._get_run_lock(workflow_id)
        with lock:                                    # 同 workflow_id 串行，不同 workflow_id 并行
            run_id = uuid.uuid4().hex
            collector = RunLogCollector(run_id)       # run-scoped 收集器（H3）：add(log)/collect()
            token = set_run_collector(collector)      # ContextVar：nodes/base.py 提供 set/get
            started_at = datetime.now()
            try:
                output = self._registry[workflow_id].invoke(input_data)
            finally:
                set_run_collector(None)               # 经 token 成对复位，ContextVar 不泄漏到后续请求
            return RunResult(
                workflow_id=workflow_id,
                run_id=run_id,
                output=output,
                execution_logs=collector.collect(),   # 运行中节点经 log_execution 写入收集器
                started_at=started_at,
                finished_at=datetime.now(),           # duration_ms 为派生属性
            )

    def _get_run_lock(self, workflow_id: str) -> threading.RLock:
        with self._meta_lock:
            return self._run_locks.setdefault(workflow_id, threading.RLock())
```

```python
# ❌ 反例：H1 现场 —— 共享实例上就地清空再收集

    node.clear_execution_history()        # 并发请求 B 正在读，被 A 清空
```

### 12.2 注册顺序与快照（对应 H5，规范约束）

- **禁止**在构建期对可变注册表做快照（原 AgentNode 构建时拷贝 workflow_registry 快照，之后注册的工作流不可见）。
- 需要引用其它工作流时，在**运行期惰性解析**（每次执行时按 id 查注册表）。本期无 AgentNode，但任何"把 registry 内容 copy 进节点实例"的写法在评审中直接打回。

### 12.3 缓存（对应 H4 / R10）

- 本期**默认不引入缓存**。
- 若未来引入，四要素缺一不可，示例：

```python
# ✅ 正例（仅作未来参考，本期不实现）：带 maxsize + TTL + 开关的缓存
class TtlCache:
    def __init__(self, maxsize: int = 128, ttl_seconds: float = 300.0, enabled: bool = False):
        self._maxsize, self._ttl, self.enabled = maxsize, ttl_seconds, enabled
        self._store: OrderedDict[str, tuple[float, Any]] = OrderedDict()

    def get(self, key: str) -> Any | None:
        if not self.enabled:
            return None
        item = self._store.get(key)
        if item is None:
            return None
        ts, value = item
        if time.monotonic() - ts > self._ttl:        # TTL 失效
            self._store.pop(key, None)
            return None
        self._store.move_to_end(key)
        return value

    def set(self, key: str, value: Any) -> None:
        if not self.enabled:
            return
        self._store[key] = (time.monotonic(), value)
        while len(self._store) > self._maxsize:      # 上限淘汰（LRU）
            self._store.popitem(last=False)
```


- 若实现缓存，测试必须覆盖：命中 / TTL 失效 / 上限淘汰 / 开关关闭时完全旁路。
